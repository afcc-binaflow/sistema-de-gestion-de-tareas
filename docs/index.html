PFO 2 — Sistema de gestión de tareas

Flask SQLite JWT (HS256) Python 3.13

API REST para gestionar tareas personales, con autenticación por JWT, persistencia en SQLite y un cliente de consola. Trabajo práctico de la materia Redes / TSDS.

Qué hace

  • Registro e inicio de sesión con contraseñas hasheadas (scrypt, vía Werkzeug).
  • CRUD completo de tareas por usuario: cada usuario ve y modifica solo las suyas.
  • Aislamiento por propietario aplicado en la consulta SQL (WHERE usuario_id = ?), no filtrando después.
  • Token JWT de 8 horas, firmado con SECRET_KEY del entorno, que viaja en el header Authorization: Bearer.
  • Cliente de consola con dos capas (transporte + presentación), timeout explícito y un solo mensaje de error por línea.
  • Página de bienvenida pública y sin datos (GET /tareas).

Arquitectura

servidor.py  ->  create_app(config)
   ├── config.py       (lee os.environ: SECRET_KEY, DATABASE_PATH)
   ├── db.py           (conexión, esquema, init_db)
   ├── repository.py   (DAO: todo el SQL)
   ├── routes.py       (capa HTTP: parsear, llamar, responder)
   └── security.py     (hashing + JWT)

cliente.py  ->  ApiDeTareas (transporte) + menu (presentación)

Cómo correrlo

# 1. Entorno
python3.13 -m venv venv
source venv/bin/activate          # o .\venv\Scripts\Activate.ps1 en Windows

# 2. Dependencias
pip install -r requirements.txt

# 3. Configurar el secreto
export SECRET_KEY="un-valor-largo-y-aleatorio"   # PowerShell: $env:SECRET_KEY = "..."

# 4. Servidor (desarrollo)
python servidor.py                # http://127.0.0.1:5000

# 5. Cliente de consola (en otra terminal)
python cliente.py

Respuestas conceptuales (resumen)

¿Por qué hashear contraseñas? Para que una filtración de la base no entregue credenciales usables: el hash es irreversible, lleva salt aleatorio (dos hashes iguales de la misma contraseña son distintos) y no tiene clave que filtrar, a diferencia del cifrado reversible. Ver la respuesta completa.

Ventajas de SQLite en este proyecto: cero configuración (viene en la stdlib), todo en un archivo, transaccional (ACID), ideal para desarrollo y baja concurrencia. Su limitación son las escrituras concurrentes (database is locked) y el filesystem efímero del hosting. Ver la respuesta completa.
